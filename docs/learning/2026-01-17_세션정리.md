### 3. bot.py 수정 - 토큰 환경변수화

**파일**: `bot.py`

**변경 전:**
```python
TELEGRAM_TOKEN = "YOUR_TELEGRAM_TOKEN_HERE"  # 실제 토큰이 하드코딩되어 있었음
GEMINI_API_KEY = "YOUR_GEMINI_API_KEY_HERE"  # 실제 API 키가 하드코딩되어 있었음
```

**변경 후:**
```python
TELEGRAM_TOKEN = os.getenv("TELEGRAM_TOKEN")
GEMINI_API_KEY = os.getenv("GEMINI_API_KEY")
```

**핵심 원리:**
- 하드코딩된 토큰은 GitHub에 올리면 노출 위험
- `os.getenv()`로 환경변수에서 읽어오면 코드와 비밀정보 분리
- `python-dotenv`의 `load_dotenv()`가 `.env` 파일을 자동 로드

### 4. .env 파일 생성

**파일**: `.env`

**내용:**
```

GEMINI_API_KEY=실제API키
```

**핵심 원리:**
- 실제 토큰을 저장하는 파일
- `.gitignore`에 추가하여 GitHub에 올라가지 않음
- 로컬에서만 사용

### 5. .env.example 파일 생성

**파일**: `.env.example`

**내용:**

**핵심 원리:**

- 실제 토큰 없이 필요한 환경변수 목록만 제공
- GitHub에 올려서 프로젝트 설정 방법 안내

## 핵심 원리

### 환경변수 분리 패턴

```
┌─────────────────────────────────────────────────────────┐
│                    환경변수 분리                          │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  코드 (bot.py)           환경변수 (.env)                  │
│  ┌──────────────┐       ┌──────────────┐                │
│  │ os.getenv()  │ ←──── │ TELEGRAM_TOKEN│                │
│  │              │       │ GEMINI_API_KEY│                │
│  └──────────────┘       └──────────────┘                │
│         │                      │                         │
│         ▼                      ▼                         │
│    GitHub 공개              로컬만 보관                    │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### .gitignore 동작 원리

```
1. git add . 실행
2. Git이 .gitignore 파일 확인
3. 패턴과 일치하는 파일 제외
4. 나머지 파일만 스테이징

.env           → 제외 (.gitignore에 명시)
.env.example   → 포함 (명시 안 됨)
bot.py         → 포함
__pycache__/   → 제외 (패턴 매칭)
```

### Git 브랜치 이름 변경

```bash
git branch -M main
```
- `-M`: 강제 이름 변경 (Move)
- `master` → `main` 변경 (GitHub 기본 브랜치)

## 배운 점

### 1. 토큰 보안 관리

| 방법 | 설명 | 보안 |
|------|------|------|
| 하드코딩 | 코드에 직접 작성 | X |
| 환경변수 | `.env` 파일 분리 | O |
| Secrets | GitHub Secrets, AWS SSM | OO |

**Best Practice:**
- 개발: `.env` 파일
- 배포: 환경변수 또는 Secrets Manager

### 2. .gitignore 패턴

```gitignore
# 특정 파일
.env

# 폴더 전체
__pycache__/

# 확장자 패턴
*.pyc
*.log

# 복합 패턴
*.py[cod]  # .pyc, .pyo, .pyd

# 부정 패턴 (제외에서 제외)
!important.log
```

### 3. python-dotenv 사용법

```python
from dotenv import load_dotenv
import os

# .env 파일 로드
load_dotenv()

# 환경변수 읽기
token = os.getenv("TELEGRAM_TOKEN")

# 기본값 설정
debug = os.getenv("DEBUG", "False")
```

### 4. Git 기본 워크플로우

```
작업 디렉토리 → Staging Area → Local Repo → Remote Repo
     │              │              │              │
   git add      git commit     git push      GitHub
```

### 5. GitHub 레포지토리 구조

```
repository/
├── README.md          # 프로젝트 소개 (필수)
├── .gitignore         # Git 제외 파일
├── .env.example       # 환경변수 템플릿
├── requirements.txt   # Python 의존성
├── LICENSE            # 라이선스
└── src/               # 소스 코드
```
